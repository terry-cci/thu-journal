### 5. 综合题：为 rCore/uCore 设计文件锁系统调用**

在 rCore/uCore 中，已有 `open/read/write/close/fork/wait/exit` 等系统调用。现在希望新增一个简化版文件锁系统调用 `sys_flock`，用于支持父子进程协同处理同一个文件。

系统调用接口如下：

```c
int flock(int fd, int operation);
```

`operation` 可取：

```c
#define LOCK_SH    1   // 共享读锁
#define LOCK_EX    2   // 排他写锁
#define LOCK_UN    3   // 解锁
#define LOCK_NB    4   // 非阻塞标志，可与 LOCK_SH/LOCK_EX 组合
#define LOCK_MAND  8   // 强制锁标志，可与 LOCK_SH/LOCK_EX 组合
```

约定如下：

1. 本题的锁只针对整个文件，不支持字节范围锁。
2. `LOCK_SH` 之间兼容；`LOCK_EX` 与任何其他锁冲突。
3. 默认是**咨询锁**：内核只在 `flock` 时检查冲突，普通 `read/write` 不主动检查锁。
4. 如果加锁时带上 `LOCK_MAND`，则该锁是**强制锁**：普通 `read/write` 也必须检查锁。
5. 锁关联到内核中的打开文件对象 `struct file`，而不是 PID。
6. `fork` 后父子进程继承文件描述符，并共享同一个 `struct file`，因此也共享同一把锁。
7. `close` 最后一个引用该 `struct file` 时，应释放它持有的锁。
8. 阻塞式加锁冲突时，进程进入睡眠；非阻塞式加锁冲突时，立即返回错误。

给出如下用户程序：

```c
int fd = open("test.txt", O_RDWR | O_CREAT | O_TRUNC);

flock(fd, LOCK_EX | LOCK_MAND);
write(fd, "Hello", 5);

pid_t pid = fork();

if (pid == 0) {
    char buf[16];
    lseek(fd, 0, SEEK_SET);
    int n = read(fd, buf, sizeof(buf));
    buf[n] = 0;
    printf("child read: %s\n", buf);
    exit(0);
} else {
    wait(NULL);
    flock(fd, LOCK_UN);
    close(fd);
}
```
