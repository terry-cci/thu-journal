# 物理内存与虚拟内存

## 关键知识点

### 虚拟内存与进程 / 线程 / 系统调用的关系

---

# 本讲主线

## 五个核心问题

1. 物理地址、虚拟地址、逻辑地址如何区分？
2. OS 如何管理有限的物理页帧？
3. 页表、TLB、`satp` 如何完成地址翻译？
4. 缺页异常、COW、页面置换如何协作？
5. 虚拟内存如何影响进程、线程和系统调用？

---

# 内存管理总体框架

```text
程序中的地址
  -> 编译/链接形成逻辑地址
  -> OS 装载形成进程虚拟地址空间
  -> MMU 按页表翻译虚拟地址
  -> 访问物理内存中的页帧

如果映射不存在或权限不满足：
  -> Page Fault
  -> 内核处理缺页或拒绝访问
```

关键结论：

- 虚拟地址空间是进程抽象的重要组成部分。
- 页表是“虚拟页 -> 物理页帧”的映射表。
- 物理内存分配通常以页帧为单位。

---

# 三类地址

| 地址 | 视角 | 含义 |
|---|---|---|
| 逻辑地址 LA | 编译器 / 链接器 | 程序中生成的地址或偏移 |
| 虚拟地址 VA | CPU / 进程 | 进程执行时看到的地址 |
| 物理地址 PA | 内存总线 / DRAM | 真正访问内存芯片的地址 |

地址生成过程：

```text
源程序 -> 编译/链接 -> 逻辑地址
加载运行 -> 虚拟地址
MMU + 页表 -> 物理地址
```

---

# 为什么需要虚拟内存？

虚拟内存的主要作用：

- 简化编译和加载：每个程序可拥有独立地址空间。
- 提供保护：页表权限限制读、写、执行和用户态访问。
- 提高利用率：物理不连续，虚拟可连续。
- 支持共享：共享库、共享内存、COW。
- 支持超越物理内存：内存 + 外存，以页为单位换入换出。

一句话：

> 虚拟内存让应用看到“连续、私有、受保护”的地址空间，而内核管理背后的真实物理页帧。

---

# 物理内存中有什么？

物理内存中通常包含：

- 内核代码、数据、栈、堆
- 用户进程的代码、数据、堆、栈
- 空闲物理页帧
- 内核管理数据结构：
  - PCB / TCB
  - `MemorySet`
  - 多级页表
  - TrapContext 页
  - 内核栈

重点：

> 物理内存不是只放用户数据；页表、内核栈和管理结构本身也占用物理页帧。

---

# 物理页帧管理

物理页面，也称页帧、Frame、Page Frame。

- 物理地址空间被划分为固定大小的页帧。
- 虚拟地址空间也被划分为相同大小的虚拟页。
- 内核维护空闲页帧集合。
- 需要时分配，进程退出或地址空间销毁时回收。

典型接口：

```text
alloc()   -> 分配空闲物理页帧
dealloc() -> 回收物理页帧
```

判断题：

| 说法 | 判断 |
|---|:---:|
| 物理页帧分配器通常以页为基本单位管理物理内存，而不是按任意字节粒度分配。 | <span class="ok">√</span> |

---

# 连续分配与碎片

| 碎片类型 | 含义 | 典型来源 |
|---|---|---|
| 外部碎片 | 分配块之间的空闲空间，单块不够大而无法利用 | 动态分区、连续分配 |
| 内部碎片 | 已分配块内部未使用空间 | 固定大小页、按 2 的幂分配 |

分页的影响：

- 基本消除外部碎片。
- 仍可能产生内部碎片，例如最后一页没用满。

判断题：

| 说法 | 判断 |
|---|:---:|
| 分页式虚拟内存管理基本消除了外部碎片，但页内未用完的空间仍可能造成内部碎片。 | <span class="ok">√</span> |

---

# 伙伴系统 Buddy System

## 适合场景

内核常需要快速分配和释放大小为 `2^k` 个页的连续物理块。

## 工作规则

- 分配时：找最小可用块；太大就不断二分。
- 释放时：如果相邻伙伴块空闲且大小相同，就合并为更大块。

判断题：

| 说法 | 判断 | 解释 |
|---|:---:|---|
| 伙伴系统释放内存块时，如果相邻伙伴块空闲且大小相同，就可以合并成更大的空闲块。 | <span class="ok">√</span> | 这是 buddy 合并的核心规则。 |

---

# 页式存储管理

页式管理的基本思想：

- 虚拟地址空间分成虚拟页 VPN。
- 物理地址空间分成物理页帧 PPN。
- 页表记录 VPN 到 PPN 的映射和权限。
- MMU 使用页表完成地址翻译。

地址翻译：

```text
虚拟地址 VA = VPN + offset
页表查 VPN -> PPN
物理地址 PA = PPN + offset
```

页内偏移不变，变化的是页号映射。

---

# 页表项 PTE

RISC-V 页表项常见字段：

| 字段 | 含义 |
|---|---|
| V | 有效位 |
| R/W/X | 可读 / 可写 / 可执行 |
| U | 用户态是否可访问 |
| A | Access，访问位 |
| D | Dirty，修改位 |
| G | 全局映射 |
| PPN | 物理页号 |

重点：

- 权限错误也可能触发异常。 A 位、D 位可辅助页面置换算法。 U 位用于区分用户态是否能访问该页。

---

# 多级页表

为什么需要多级页表？

- 单级页表可能非常大。
- 多级页表只为实际使用的虚拟地址范围分配下级页表页。
- 下级页表可以按需创建。

判断题：

| 说法 | 判断 | 解释 |
|---|:---:|---|
| 多级页表要求进程创建时一次性分配完整的所有层级页表，否则地址翻译无法进行。 | <span class="bad">×</span> | 多级页表可以按需分配下级页表页。 |

---

# RISC-V 的 satp

`satp`：Supervisor Address Translation and Protection。

| 字段 | 作用 |
|---|---|
| MODE | 是否开启分页，选择页表模式 |
| ASID | 地址空间标识，可降低上下文切换时 TLB 刷新开销 |
| PPN | 根页表的物理页号 |

在教学 OS 中：

```text
TCB -> MemorySet -> PageTable -> root_ppn -> satp
```

切换进程地址空间，本质上常涉及切换当前使用的页表根。

---

# TLB 是什么？

TLB：Translation Lookaside Buffer，页表项缓存。

作用：

- 缓存最近使用过的虚拟页到物理页帧映射。
- 减少每次访存都遍历页表的开销。

关键区别：

| 事件 | 含义 |
|---|---|
| TLB hit | 快表命中，直接得到 PPN |
| TLB miss | 快表未命中，需要查页表 |
| Page Fault | 页表无有效映射、权限不满足或页不在内存 |

---

# TLB miss 不等于缺页

判断题：

| 说法 | 判断 | 解释 |
|---|:---:|---|
| TLB miss 一定会导致缺页异常，因为页表里一定没有对应的虚拟页映射。 | <span class="bad">×</span> | TLB miss 只表示 TLB 未命中，页表里仍可能有合法映射。 |

正确过程：

```text
访问 VA
  -> TLB miss
  -> 查页表
     -> PTE 有效且权限满足：填入 TLB 后继续
     -> PTE 无效或权限不满足：触发异常
```

---

# 虚拟存储

虚拟存储 = 内存 + 外存。

基本思想：

- 常用页留在物理内存。
- 不常用页放到外存。
- 需要访问而不在内存时，触发缺页异常，由 OS 调入。
- 内存不足时，选择某些页换出。

前提：

> 程序具有局部性。

---

# 局部性原理

| 类型 | 含义 | 例子 |
|---|---|---|
| 时间局部性 | 最近访问过的内容将来还可能访问 | 循环变量、热点函数 |
| 空间局部性 | 访问某地址附近的地址概率高 | 数组顺序扫描 |
| 分支局部性 | 跳转常落在相近或固定路径 | 条件分支常走同一分支 |

意义：

- 按需调页才有意义。
- LRU、Clock、工作集等算法都在利用局部性。

---

# 缺页异常 Page Fault

Page Fault 是同步异常，不是中断。

触发原因：

- 虚拟页没有有效映射。
- 页面在外存，不在物理内存。
- 权限不满足，例如写只读页。
- COW 写共享只读页。

判断题：

| 说法 | 判断 |
|---|:---:|
| 在 RISC-V 上，Page Fault 是一种异常而不是中断，发生时 `sepc` 保存触发缺页那条指令的地址。 | <span class="ok">√</span> |

---

# 缺页异常处理流程

```text
CPU 访问虚拟地址
  -> TLB 未命中，查页表
  -> PTE 无效 / 不在内存 / 权限问题
  -> 触发 Page Fault
  -> OS 判断地址是否合法
  -> 找到外存页面或准备新物理页
  -> 若有空闲页帧，直接调入
  -> 若无空闲页帧，页面置换
  -> 修改页表项，设置有效位和权限
  -> 返回用户态，重新执行触发缺页的指令
```

重点：

> 缺页处理完成后，通常重新执行触发缺页的那条指令。

---

# Copy-on-Write

COW 用于优化 `fork()`。

fork 时：

- 不立即复制所有物理页。父子进程页表指向同一批物理页。将共享页标为只读。

写入时：

- 触发写保护缺页异常。内核分配新物理页。复制旧页内容。修改写入方页表为可写私有页。

判断题：

| 说法 | 判断 |
|---|:---:|
| COW 的核心是 fork 时共享只读物理页，直到有写入时再复制。 | <span class="ok">√</span> |

---

# 页面置换算法

触发时机：

- 发生缺页，需要调入新页。
- 没有足够空闲物理页帧。
- OS 必须选一个页换出。

设计目标：

- 减少缺页次数。
- 减少换入换出。
- 尽量换出未来不再访问或短期不用的页。

分类：

| 类型 | 置换范围 |
|---|---|
| 局部置换 | 当前进程占有的页 |
| 全局置换 | 系统中所有可换出的页 |

---

# OPT / FIFO / LRU

| 算法 | 换出对象 | 特点 |
|---|---|---|
| OPT | 未来最久不再访问的页 | 理论最优，实际无法精确实现 |
| FIFO | 最早进入内存的页 | 简单，但可能换出热点页 |
| LRU | 最久未被访问的页 | 用过去近似未来，常用但精确实现开销大 |

重点：

- OPT 需要未来访问序列，实际 OS 不知道未来。
- FIFO 可能出现 Belady 现象。
- LRU 是栈式算法，不会出现 Belady 现象。

---

# Clock 与改进 Clock

Clock：

- 页面组织成环形队列。
- 依靠访问位 A。
- 缺页时扫描：
  - A=0：换出。
  - A=1：清零，给第二次机会，继续扫描。

改进 Clock：

- 增加修改位 D。
- 优先换出未访问、未修改的页。
- 避免优先换出脏页，因为脏页写回外存更贵。

易错点：

> 改进型 Clock 扫描时遇到 A=1 的页会清零，不是专门“第二轮才清零”。

---

# Belady 现象

Belady 现象：

> 分配给进程的物理页帧数增加，缺页次数反而增加。

常见结论：

| 算法 | 是否可能出现 Belady |
|---|---|
| FIFO | 可能 |
| LRU | 不会 |
| OPT | 不会 |

原因：

- LRU 属于栈式算法。
- 栈式算法中，页帧数更多时包含的页面集合覆盖比页帧数少时包含的页面集合。

---

# 工作集与常驻集

工作集：

> 进程在当前时刻前一段窗口内实际访问过的页面集合。

常驻集：

> 当前实际驻留在物理内存中的页面集合。

关系：

- 工作集是进程访存局部性的表现。
- 常驻集取决于 OS 分配给进程的物理页数和置换算法。
- 常驻集能覆盖工作集时，缺页率较低。
- 常驻集小于工作集时，容易频繁缺页。

---

# 工作集算法与抖动

工作集置换算法：

- 只保留当前工作集中的页面。
- 换出不在工作集中的页面。
- 属于局部置换思想，因为它关注单个进程近期访问行为。

抖动 Thrashing：

- 进程分到的物理页太少，不能容纳工作集。
- 大量时间花在换页上。
- CPU 利用率反而下降。

判断题：

| 说法 | 判断 |
|---|:---:|
| 工作集页面置换算法是局部置换算法的一种，因为它只考虑单个进程的访问行为。 | <span class="ok">√</span> |

---

# 虚拟内存与进程

进程和虚拟内存的关系：

- 每个进程通常有独立地址空间。
- PCB / TCB 中会间接保存页表根或地址空间对象。
- 创建进程时，内核创建新的 `MemorySet` 和页表。
- 切换进程时，可能切换 `satp`。
- 进程退出时，回收其页表和物理页帧。

典型包含关系：

```text
Process / Task
  -> PCB / TCB
  -> MemorySet
  -> PageTable + MapArea
  -> 物理页帧
```

---

# 虚拟内存与线程

同一进程内线程通常：

- 共享同一个地址空间。
- 共享代码段、数据段、堆。
- 共享打开文件表等进程资源。
- 各自拥有独立栈和寄存器上下文。

因此：

- 同一进程内线程切换通常不需要切换页表。
- 不同进程的线程切换通常需要切换地址空间。
- 一个线程越界写共享堆数据，会影响同进程其他线程。
- 一个线程写自己的栈，通常不会覆盖其他线程栈。

---

# 虚拟内存与系统调用

系统调用进入内核后，内核面对的是用户虚拟地址。例如：

```c
write(fd, user_buf, len);
read(fd, user_buf, len);
```

内核不能直接相信 `user_buf`：

- 地址可能未映射。
- 权限可能不允许读/写。
- 缓冲区可能跨多个页。
- 用户可能传入恶意地址。

所以内核需要：

- 根据当前进程页表翻译用户地址。做权限检查。
- 使用 `copy_from_user` / `copy_to_user` 类机制。

---

# 用户缓冲区翻译

在地址空间隔离后，`sys_write` 不能直接访问用户空间数据。

典型路径：

```text
用户传入 buf 虚拟地址
  -> 内核获取当前进程页表
  -> 按页翻译用户虚拟地址到物理地址
  -> 再找到内核可访问的映射
  -> 拷贝数据到内核或设备
```

rCore/uCore 风格实现中，页表模块常提供类似：

```rust
translated_byte_buffer()
```

用于把用户缓冲区转换为内核可访问的片段集合。

---

# 用户态 / 内核态地址空间切换

教学 OS 中常见设计：

- 应用地址空间：限制用户程序可访问范围。
- 内核地址空间：内核管理整个物理内存和设备映射。
- trap 发生时，要保存 TrapContext。
- 用户态进入内核态时，可能需要切换页表和内核栈。
- 返回用户态时，再切回用户进程地址空间。

关键难点：

> trap 发生时，CPU 仍处于当前地址空间上下文中；内核必须设计跳板页或固定映射，保证切换页表前后代码能继续执行。

---

# 虚拟内存与 fork / exec

`fork()`：

- 复制父进程地址空间的逻辑内容。
- 可通过 COW 共享物理页，延迟复制。
- 父子写同一虚拟地址互不影响。

`exec()`：

- 丢弃当前用户地址空间内容。
- 根据 ELF 创建新的代码、数据、堆、栈映射。
- PID 可保持不变，但程序映像已替换。

重点：

> fork 后“内存内容相同”不等于“共享同一可写物理页”。语义上父子地址空间独立。

---

# mmap / brk 与地址空间

系统调用可动态调整进程地址空间：

| 系统调用 | 典型作用 |
|---|---|
| `brk` / `sbrk` | 调整堆顶，扩展或收缩堆 |
| `mmap` | 建立一段虚拟地址映射，可映射匿名内存或文件 |
| `munmap` | 取消映射，回收相关资源 |

内核需要更新：

- `MemorySet` / `MapArea`
- 页表项
- 物理页帧引用和权限

# 高频判断题汇总

| 说法 | 判断 | 解释 |
|---|:---:|---|
| Page Fault 是异常不是中断，`sepc` 保存触发缺页的指令地址。 | <span class="ok">√</span> | 同步异常。 |
| LRU 不会出现 Belady 现象，因为它属于栈式算法。 | <span class="ok">√</span> | 页帧增加不会让已有集合变差。 |
| 改进型 Clock 在第二轮扫描时才清第一轮页面的 A 位。 | <span class="bad">×</span> | 扫描遇到 A=1 就可清零。 |
| 工作集算法只考虑单个进程访问行为，属于局部置换思想。 | <span class="ok">√</span> | 工作集描述单进程近期访问页集合。 |

# 总结

## 物理内存

- 以页帧为基本单位管理。
- 内核维护空闲页帧，分配给数据页、页表页、内核栈等。
- 伙伴系统适合快速分配 2 的幂大小连续块。

## 虚拟内存

- 为进程提供独立、受保护的地址空间。
- 页表完成 VPN -> PPN 映射，TLB 缓存地址翻译。
- 缺页异常由当前访存同步触发，处理后通常重试指令。
- 页面置换依靠局部性降低缺页率。

---

# 总结：关系

## 与进程

- 每个进程通常拥有自己的地址空间和页表。
- 进程切换可能切换 `satp` 和 TLB 状态。
- `fork`、`exec`、`exit` 都会改变或回收地址空间。

## 与线程

- 同进程线程共享地址空间和堆。
- 各线程有独立栈和寄存器。
- 同进程线程切换通常不需要换页表。

## 与系统调用

- 用户指针是用户虚拟地址。
- 内核必须查当前进程页表并检查权限。
- `copy_to_user` / `copy_from_user` 是安全边界。
