# 系统调用、中断、异常、进程与线程

## 关键知识点



---

# 本讲主线

## 四个核心问题

1. 用户程序为什么不能直接访问硬件和内核数据？
2. 系统调用、中断、异常都叫 trap，它们有什么区别？
3. 操作系统如何用进程抽象管理程序执行？
4. 线程为什么比进程轻，轻在哪里？

---

# 总体框架

```text
用户程序
  |
  | ecall / syscall
  v
Trap 入口
  |
  | 保存上下文、切换特权级、分派处理
  v
内核服务
  |
  | 进程管理 / 文件系统 / 内存管理 / 设备驱动 / IPC
  v
硬件资源
```

关键结论：

- 用户态只能通过受控入口请求服务。
- 系统调用、异常、中断都让控制流进入内核。
- 进程和线程是内核组织并发执行的核心抽象。

---

# 用户态与内核态

| 对比项 | 用户态 U-Mode | 内核态 S-Mode |
|---|---|---|
| 运行对象 | 应用程序 | 操作系统内核 |
| 权限 | 非特权，不能执行特权指令 | 特权，可管理硬件和应用 |
| 可访问资源 | 自己的用户地址空间 | 内核数据结构、页表、设备等 |
| 典型入口 | 普通函数调用 | trap 入口、系统调用分派 |
| 退出方式 | `ecall` 请求内核 | `sret` 返回用户态 |

重点：

> 用户程序不能直接访问内核数据结构，也不能直接控制设备。必须通过系统调用等受控入口。

---

# RISC-V 特权级

| 特权级 | 名称 | 典型软件 | 跨级指令 |
|---|---|---|---|
| U | User | 应用程序 | `ecall` |
| S | Supervisor | OS 内核 | `sret`、`ecall` |
| M | Machine | Bootloader / SBI / 固件 | `mret` |

RISC-V 中常见组合：

- 教学 OS 常重点关注 U-Mode 与 S-Mode。
- M-Mode 权限最高，常负责底层初始化、SBI、时钟等。
- U-Mode 不能执行 `sret`、修改大部分 CSR、直接访问内核资源。

---

# 系统调用是什么？

## 定义

系统调用是用户程序主动请求内核服务的机制。

典型流程：

```text
用户程序调用 libc 封装
  -> 设置 syscall 编号和参数
  -> 执行 ecall / syscall 指令
  -> 硬件进入内核 trap 入口
  -> 内核按编号分派到 sys_xxx
  -> 检查参数并执行内核服务
  -> 设置返回值
  -> 恢复上下文并返回用户态
```

重点：

- 系统调用看起来像函数调用，本质是特权级切换。
- `ecall` 触发的是同步异常，不是外部中断。

---

# 系统调用的常见服务

| 服务类型 | 典型系统调用 | 作用 |
|---|---|---|
| 进程管理 | `fork` `exec` `wait` `exit` `getpid` | 创建、装载、等待、退出进程 |
| 文件与 I/O | `open` `read` `write` `close` | 统一访问文件、终端、设备 |
| 内存管理 | `mmap` `brk` | 申请或映射地址空间 |
| IPC | `pipe` `signal` `socket` | 进程间通信和事件通知 |

常见误区：

> `write(fd, buf, n)` 不是用户程序直接写设备，而是内核根据 fd 找到文件对象或设备对象后完成输出。

---

# 一次系统调用的内核工作

以 `read(fd, buf, len)` 为例：

1. 检查系统调用号与参数数量。
2. 根据当前进程 fd 表找到内核 file 对象。
3. 检查 file 是否可读。
4. 根据 file 类型分派到普通文件、管道、终端或设备。
5. 检查用户缓冲区地址 `buf` 是否有效。
6. 使用 `copy_to_user` 类机制把数据写回用户空间。
7. 更新状态并返回。

重点：

- 用户指针不能直接信任。
- fd 是fd 表的索引，不是磁盘块号，也不是内核对象本身。

---

# 中断、异常、系统调用

| 类型 | 触发源 | 同步/异步 | 例子 | 典型作用 |
|---|---|---|---|---|
| 系统调用 | 用户程序主动执行 `ecall` | 同步 | `read` `write` `fork` | 请求内核服务 |
| 异常 | 当前指令执行导致 | 同步 | 缺页、非法指令、除零 | 处理错误或补齐资源 |
| 中断 | 外部设备或定时器 | 异步 | 时钟中断、磁盘中断 | 抢占调度、I/O 完成通知 |

重点：

> 它们都会让 CPU 进入 trap 处理流程，由更高特权级软件接管控制权。

---

# 同步与异步

## 同步事件

- 与当前执行指令直接相关。
- 可认为“这条指令造成了这个事件”。例子：`ecall`、缺页异常、非法指令。

## 异步事件

- 与当前正在执行哪条指令没有直接因果关系。
- 来自外设或定时器。例子：时钟中断、外部设备中断。

判断题常见说法：

| 说法 | 判断 |
|---|:---:|
| `ecall` 属于异常，不是外部中断 | <span class="ok">√</span> |
| 外部中断通常由外设异步触发 | <span class="ok">√</span> |

---

# Trap 处理时硬件做什么？

以 RISC-V 为例，trap 发生时硬件通常会：

1. 保存发生 trap 相关的 PC 到 `sepc` / `mepc`。
2. 在 `scause` / `mcause` 中记录 trap 原因。
3. 在 `stval` / `mtval` 中记录附加信息，例如出错地址。
4. 根据 `stvec` / `mtvec` 跳转到 trap 入口。
5. 更新中断使能与先前特权级相关状态。

软件随后负责：

- 保存通用寄存器上下文。
- 分派到系统调用、异常处理或中断处理逻辑。
- 恢复上下文并返回。

---

# 重要 CSR

| CSR | 作用 |
|---|---|
| `stvec` | S-Mode trap 入口地址 |
| `sepc` | 发生 trap 时的程序计数器 |
| `scause` | trap 原因，中断/异常类型 |
| `stval` | trap 附加信息，如缺页地址 |
| `sstatus` | 中断使能、先前特权级等状态 |
| `satp` | 页表根地址与地址空间配置 |

重点：

- Page Fault 是异常，不是中断。
- 缺页异常发生时，`sepc` 通常保存触发缺页的指令地址。
- 缺页处理完成后，通常重新执行那条指令。

---

# 时钟中断与抢占式调度

## 为什么需要时钟中断？

如果没有时钟中断，用户程序可能长期占用 CPU。

时钟中断使内核可以：

- 定期获得 CPU 控制权。
- 统计运行时间。
- 判断时间片是否用完。
- 触发抢占式调度。

重点：

> 发生时钟中断时，内核可以借此进行抢占式调度，让当前运行进程让出 CPU。

---

# 中断处理程序的约束

中断处理程序应尽量短小。

原因：

- 中断上下文通常不能随意阻塞。
- 持续占用中断上下文会影响系统响应。
- 长时间关中断会延迟其他中断。
- I/O 完成后常只做状态更新和唤醒，复杂处理留给普通内核线程或进程上下文。

判断题：

| 说法 | 判断 | 解释 |
|---|:---:|---|
| 中断处理程序应该尽量短小，通常不应在中断上下文中执行可能阻塞的操作 | <span class="ok">√</span> | 中断上下文不能像普通进程一样睡眠等待 |

---

# 异常：以缺页为例

缺页异常的典型路径：

```text
用户程序访问虚拟地址
  -> 页表中无有效映射或权限不满足
  -> CPU 触发 Page Fault
  -> trap 进入内核
  -> 内核检查地址是否合法
  -> 分配物理页或从磁盘调页
  -> 修改页表并刷新必要的 TLB 状态
  -> 返回用户态，重新执行触发缺页的指令
```

重点：

- 缺页异常是同步异常。
- 它不是外部设备异步打断。
- 正常缺页处理后，原访存指令通常还能继续成功执行。

# 进程为什么重要？

## 进程提供的两个关键抽象

1. 独立的逻辑控制流  
   好像每个程序独占 CPU。

2. 私有地址空间  
   好像每个程序独占内存。

从实现角度看：

> 进程是操作系统为了管理程序动态执行过程而建立的数据结构和操作过程。

从资源角度看：

> 进程是程序执行中占用资源的集合，包括 CPU 时间、地址空间、文件、I/O 等。

---

# 程序、进程、任务

| 概念 | 含义 |
|---|---|
| 程序 | 静态的可执行文件或代码集合 |
| 进程 | 程序的一次动态执行过程 |
| 任务 | 在教学 OS 中常与进程接近，早期或简化阶段的执行实体 |

关键区别：

- 程序是静态的，进程是动态的。
- 同一个程序可以有多个进程实例。
- 进程 = 程序 + 数据 + 执行状态 + OS 管理信息。

---

# 进程控制块 PCB

PCB 是操作系统管理进程的核心数据结构。

常见内容：

- PID、父子关系
- 进程状态
- 寄存器上下文：PC、SP、通用寄存器等
- 地址空间信息：页表根、内存区域
- 打开文件表
- 调度信息：优先级、时间片、队列位置
- 退出状态、等待关系

重点：

> PCB 是进程存在的内核侧标志；上下文切换依赖保存和恢复 PCB 中的执行上下文。

---

# 进程状态模型

```text
创建
  |
  v
就绪 <---------+
  |            |
  | 调度       | 抢占 / I/O 完成 / 事件唤醒
  v            |
运行 -----> 阻塞
  |
  | exit / 被杀死
  v
退出
```

关键状态：

- 就绪：可以运行，只是还没被调度到 CPU。
- 运行：正在 CPU 上执行。
- 阻塞：等待某个事件完成，暂时不能运行。

---

# 状态转换

| 转换 | 触发原因 |
|---|---|
| 就绪 -> 运行 | 调度器选中该进程 |
| 运行 -> 就绪 | 时间片耗尽、被更高优先级任务抢占 |
| 运行 -> 阻塞 | 等待 I/O、锁、管道数据、子进程退出等 |
| 阻塞 -> 就绪 | 等待事件完成，被内核唤醒 |
| 运行 -> 退出 | 调用 `exit` 或被终止 |

易错点：

> 阻塞态进程不是“时间片到了”就自动回到就绪态。它等待的是事件完成。

---

# 进程切换

进程切换过程：

1. 暂停当前运行进程。
2. 保存当前进程上下文到 PCB。
3. 调度器从就绪队列选择下一个进程。
4. 恢复下一个进程的上下文。
5. 必要时切换地址空间和页表。

进程切换通常需要：

- 保存/恢复寄存器
- 切换内核栈
- 切换页表或地址空间
- 更新调度队列和状态

---

# 协作式调度与抢占式调度

| 调度方式 | CPU 让出方式 | 依赖机制 | 特点 |
|---|---|---|---|
| 协作式调度 | 进程主动放弃 CPU | `yield`、阻塞系统调用 | 简单，但恶意或错误程序可能长期占用 CPU |
| 抢占式调度 | 进程被动让出 CPU | 时钟中断、优先级抢占 | 响应性好，是现代 OS 常用方式 |

重点：

- 时间片轮转依赖抢占机制。
- 时间片太短会带来大量上下文切换，降低吞吐量。

---

# fork / exec / wait / exit

| 系统调用 | 作用 |
|---|---|
| `fork()` | 创建子进程，复制父进程上下文 |
| `exec()` | 用新程序映像替换当前进程内容 |
| `wait()` / `waitpid()` | 父进程等待子进程退出并获取状态 |
| `exit()` | 当前进程终止，报告退出状态 |

UNIX 经典组合：

```text
shell
  -> fork 创建子进程
  -> 子进程 exec 新程序
  -> 父进程 wait 子进程结束
```

---

# fork 的关键语义

`fork()` 后：

- 父子进程拥有几乎相同的内存内容。
- 父子进程有独立地址空间。
- 对同一个虚拟地址的写入互不影响。
- 返回值不同：
  - 子进程返回 0
  - 父进程返回子进程 PID

实现优化：

- Copy-on-Write 常用于避免 fork 时立即复制全部物理页。
- COW 不改变语义，只改变复制时机。

---

# exec 的关键语义

`exec()` 的作用：

- 在当前进程中加载新程序。
- 替换原来的代码、数据、堆栈等用户态映像。
- PID 通常不变。
- 成功后不返回到原程序的下一行。

易错点：

```c
if (fork() == 0) {
    exec("program", ...);
    printf("only runs if exec fails\n");
}
```

---

# 线程为什么出现？

进程的不足：

- 进程间地址空间隔离，数据共享不方便。
- 通过 IPC 交换数据成本较高。
- 创建、销毁、切换进程开销较大。
- 一个应用内部可能需要多个并发控制流。

线程的目标：

- 在同一进程资源环境中提供多个执行流。
- 让共享内存和共享文件更方便。
- 降低并发执行的时间和空间开销。

---

# 线程的定义

线程是进程内的指令执行流，是 CPU 调度的基本单位。

| 对比项 | 进程 | 线程 |
|---|---|---|
| 主要角色 | 资源分配单位 | CPU 调度单位 |
| 地址空间 | 通常独立 | 同进程线程共享 |
| 打开文件表 | 进程拥有 | 同进程线程共享 |
| 私有内容 | PCB、地址空间等 | 寄存器、PC、栈、TCB |
| 切换开销 | 通常较大 | 同进程内通常较小 |

---

# 线程共享什么？独占什么？

同一进程内线程通常共享：

- 地址空间
- 代码段、数据段、堆
- 全局变量
- 打开文件表
- 进程级资源

每个线程通常独有：

- 程序计数器 PC
- 寄存器上下文
- 用户栈 / 内核栈
- 线程控制块 TCB

易错点：

> 同一进程内线程不共享同一个用户栈。否则局部变量会互相覆盖，线程就无法独立执行。

---

# 线程状态与切换

线程也有类似状态：

- 就绪
- 运行
- 阻塞

线程切换：

- 同一进程内线程切换通常不需要切换地址空间。
- 需要切换线程私有的寄存器、PC、栈等。
- 不同进程中的线程切换仍可能涉及页表和地址空间切换。

重点：

> “线程切换一定不切页表”说法过绝对；同一进程内通常不用，不同进程间仍可能要切。

---

# 用户级线程与内核级线程

| 类型 | 管理者 | 内核是否可见 | 优点 | 主要问题 |
|---|---|---|---|---|
| 用户级线程 M:1 | 用户态线程库 | 不可见 | 切换快、灵活 | 一个线程阻塞系统调用可能阻塞整个进程 |
| 内核管理用户线程 1:1 | 内核 | 可见 | 一个线程阻塞不影响其他线程 | 创建和切换要进入内核，开销更高 |
| 内核线程 | 内核 | 可见 | 可执行内核后台任务 | 运行在内核态 |
| 混合线程 M:N | 用户库 + 内核 | 部分可见 | 灵活 | 实现复杂 |

---

# 用户级线程的典型误区

判断题/选择题高频说法：

| 说法 | 判断 | 解释 |
|---|:---:|---|
| 用户级线程切换不需要内核参与，因此可以很快 | <span class="ok">√</span> | 在线程库内部完成 |
| 一个用户级线程阻塞在系统调用中，其他用户级线程一定还能继续运行 | <span class="bad">×</span> | 纯 M:1 模型下内核可能阻塞整个进程 |
| 内核管理的用户线程中，一个线程阻塞不一定影响同进程其他线程 | <span class="ok">√</span> | 内核能分别调度线程 |

---

# 进程 vs 线程

| 问题 | 答案 |
|---|---|
| 谁是资源分配单位？ | 进程 |
| 谁是 CPU 调度单位？ | 线程 |
| 同进程线程共享地址空间吗？ | 通常共享 |
| 同进程线程共享栈吗？ | 通常不共享 |
| 同进程线程共享打开文件表吗？ | 通常共享 |
| 线程需要自己的上下文吗？ | 需要，寄存器、PC、栈等 |
| 进程切换一定比线程切换慢吗？ | 通常更重，但不能脱离实现绝对化 |

---

# 典型判断题汇总

| 说法 | 判断 | 解释 |
|---|:---:|---|
| 系统调用是用户程序主动执行特定指令陷入内核，而外部中断通常由外设异步触发。 | <span class="ok">√</span> | 系统调用同步，外部中断异步。 |
| 在 RISC-V 中，`ecall` 触发的系统调用属于异常，而不是外部中断。 | <span class="ok">√</span> | `ecall` 是环境调用异常。 |
| 发生时钟中断时，内核可以借此进行抢占式调度。 | <span class="ok">√</span> | 时钟中断让内核定期获得控制权。 |
| 缺页异常处理完成后，通常会让触发缺页的那条指令重新执行。 | <span class="ok">√</span> | 补齐映射后重试。 |

# 典型判断题汇总

# 典型判断题汇总

| 说法 | 判断 | 解释 |
|---|:---:|---|
| 线程拥有独立寄存器上下文和执行流，但通常共享所属进程地址空间、堆和打开文件表。 | <span class="ok">√</span> | 线程是进程内执行流。 |

# 选择题：线程和进程

## 正确表述

> 同一进程里的所有线程共享同一份打开文件表，但每个线程有自己独立的用户栈。

为什么其他常见选项错？

- “线程切换比进程切换慢”通常不对。
- “用户级线程任意一个阻塞都不影响其他线程”不对。
- “内核级线程的用户态栈一定在内核地址空间”说法不严谨。

答题策略：

> 看到“共享资源 + 独立执行上下文”通常是在考线程本质。

# 选择题的思考

| 关键词 | 应想到 |
|---|---|
| `ecall` | 同步异常、系统调用 |
| 外设触发 | 异步中断 |
| 时钟中断 | 抢占式调度、时间片 |
| 缺页异常 | 同步异常、`sepc`、重试指令 |
| 阻塞态 | 等事件，不等时间片 |
| `fork` | 父子逻辑地址空间独立、返回值不同 |
| 同一进程线程 | 共享地址空间和打开文件，各有栈和寄存器 |
| 用户级线程阻塞 | 可能阻塞整个进程 |

# 常见混淆点

| 容易混淆 | 正确区分 |
|---|---|
| 系统调用 vs 普通函数调用 | 系统调用会跨特权级，普通函数调用不跨 |
| 中断 vs 异常 | 中断异步来自外部；异常同步来自当前指令 |
| Page Fault vs TLB miss | Page Fault 是无有效映射或权限问题；TLB miss 可能页表中有映射 |
| 进程 vs 程序 | 进程是程序的一次执行过程 |
| 阻塞 vs 就绪 | 阻塞不能运行；就绪能运行但未被调度 |
| 线程共享栈 | 错，线程通常各有自己的栈 |

# 总结

## 系统调用、中断、异常

- 都进入 trap 流程。
- 系统调用和异常是同步事件。
- 外部中断是异步事件。
- `ecall` 是异常；时钟中断可触发抢占；缺页处理后通常重试指令。

## 进程与线程

- 进程提供独立控制流和私有地址空间抽象。
- PCB 保存进程管理和上下文信息。
- 线程是进程内执行流，共享进程资源，但有独立栈和寄存器。
- 同进程线程切换通常比进程切换轻。
